# 改修計画 v5（評価で挙げた課題10件＋データベース）

前回の評価で挙げた10件と、追加の依頼（データベースでプレイ情報とセーブを扱い、無料で運営する）の仕様。
各項目の「洗い出した問題」は、仕様を詰める途中で見つかった穴と、その対処。決まった選択肢：

- 敵の見た目：今の絵の色替え＋演出
- 速度：段階的に解放
- 分割：`src/` に分けて結合
- テストプレイとセーブ：データベース（無料枠）

## 0. サーバーとデータベース（新規）

**構成**
- 今の Vercel プロジェクト（magia-tower-f）に `api/` を追加し、Vercel Functions（Node）で動かす。
- データベースは **Upstash Redis**（Vercel の Storage → Marketplace から無料プランで追加）。
- 依存パッケージは入れない。Upstash の REST API を Node 組み込みの `fetch` で呼ぶ。
  ルートに `package.json` を置かないので、Vercel の公開の仕組み（静的ファイル＋`api/`）は今のまま変わらない。
- 環境変数：
  - `KV_REST_API_URL` / `KV_REST_API_TOKEN`：Upstash を接続すると自動で入る（`UPSTASH_REDIS_REST_URL` / `_TOKEN` でも可）。
  - `ADMIN_TOKEN`：集計画面を見るための合言葉。ユーザーが設定する。
- データベースが未接続のときは、`/api/health` が `{db:false}` を返す。ゲームはクラウド機能を「準備中」と表示し、普段どおり遊べる。
  **ゲームは常に端末内のセーブで動き、通信はすべて「失敗しても何も起きない」作りにする。**

**無料枠の目安と、超えないための仕組み**
- Upstash の無料枠（ストレージ 256MB、月50万コマンド）と、Vercel Hobby の関数の無料枠に収まるように作る。
- 送信はまとめて行い、リクエストの回数を減らす。
  - プレイ情報：ランの終わり、5分ごと（画面が表示されている間）、画面を閉じるとき。
  - クラウドセーブ：10分ごと、転生したとき、画面を閉じるとき。
- 1リクエストあたりのコマンドは2〜4個にする（パイプラインで送る）。
- 上限を設ける：
  - 端末ごとに1日あたりのプレイ情報は2,000件まで。
  - IP（ハッシュ化して1日で消す）ごとに1日あたりのリクエスト数に上限。
  - 本文は64KB（プレイ情報）／256KB（セーブ）まで。
- 古いプレイ情報は月ごとのリストに入れ、3か月より前のものは消す（集計画面を開いたときに掃除する）。月ごとの件数にも上限を設ける。
- 無料枠を使い切ると Upstash がエラーを返す。サーバーは503を返し、ゲーム側はそれを無視する（遊びには影響しない）。

**ローカル開発とテスト**
- `tools/devserver.js`：静的ファイルと `api/` を、Upstash REST 互換の擬似サーバー（メモリ上）でまとめて動かす。
- テストもこの擬似サーバーを使うので、本番と同じコードの道筋を通る。

**洗い出した問題と対処**
- 誰でも API を叩けるので、荒らしで容量を埋められる危険がある。→ 上の各上限と、形式の検査（イベント種別は許可リスト、数値は範囲内）で防ぐ。
- IP アドレスは個人情報に近い。→ 保存しない。レート制限のキーには、ハッシュ（塩付き）を1日だけ使う。
- 関数のコールドスタートで応答が遅れうる。→ 送信は待たずに裏で行い、画面を止めない。
- 画面を閉じるときの送信（keepalive / sendBeacon）は、ブラウザの制限で約64KBまで。→ それより大きいセーブは、閉じるときには送らない。10分ごとと転生時の保存を本線にする。前回から変わっていないセーブは送らない。
- 私のテストやデバッグのプレイが、本番のデータに混ざる。→ localhost と `?debug=1` では送信しない。テストは擬似サーバーだけを使う。
- 引き継ぎコードとパスワードをセーブの中に入れると、書き出したセーブを人に渡したときに一緒に漏れる。→ セーブとは別のキー（`magiaTower.cloud.v1`）に保存する。
- 放置されたアカウントで容量が埋まる。→ セーブは最後の保存から1年で自動的に消える（保存のたびに期限を延ばす）。
- 1時間遊んだときに使う量の見積もり：
  - コマンド：プレイ情報 約12回×3コマンド＋セーブ 約6回×7コマンド ≈ 80コマンド。無料枠の月50万コマンドで、全員合計で約6,000時間分。
  - 関数の呼び出し：約18回。
- `privacy.html` には運営者の名前と連絡先が必要。→ ユーザーに入れてもらう欄を作り、報告で依頼する。

## 1. 苦難の難易度の見直し

**目標の定義（時間ではなく手間で測る）**
- 基準 B ＝「苦難を始められる頃の状態（転生直後・実績あり・過去の苦難の報酬なし）から、苦難なしで100階を倒すまでの手間」。
- 手間 ＝ 自動プレイ（AUTO＋周回＋ラン間に基本強化を一括購入）で、100階撃破までに使ったカードの枚数。
- 目標：★ ≈ B×2〜3、★★ ≈ B×4〜6、★★★ ≈ B×8〜12。どれも単独で必ずクリアできること。
- 24種すべてを2シードずつ測り、外れているものだけ数値を直す（制限の強さを直し、報酬は変えない）。

**洗い出した問題と対処**
- レベル倍率を掛け算にした影響で、苦難の効き方が変わった。忘却★★★（レベル無効）は以前よりずっと重く、鈍刃（攻撃力）は相対的に軽い。→ 方向ごとに測り直す。
- 前回「堅牢★★★が1時間半で片付く」と書いたのは、速度×4の時間で数えた値だった。手間に直すと、通常の初撃破の約4倍。→ 今回から評価は手間で統一する。
- 測定に時間がかかる（24種×2シード）。→ 並列で回し、外れたものだけ測り直す。

## 2. オートと速度

- AUTO×1は人と同じくらいの間隔にする（1枚あたり約0.6秒＝カード演出0.16秒＋間0.44秒）。
- ×2はラスボス初撃破で解放、×4は500階クリアで解放。
- 周回は今のまま、ラスボス初撃破で解放。
- 放置収入は変えない（以前は放置が稼ぎの9割を占めていたので、周回が増えて釣り合いが戻る）。

**洗い出した問題**
- 今×2や×4に設定しているセーブが、未解放の速度のまま残る。→ 今の `gameSpeed()` は解放済みの速度しか返さないので、自動で×1になる。解放されれば元の設定に戻る。
- 速度ボタンの表示：未解放の速度は、ボタンの説明に解放条件を出す。

## 4. プレイ情報の収集（データベース）

**同意**
- 初めて起動したとき（既存のプレイヤーは次の起動時）に、1度だけ選んでもらう：
  「ゲームを良くするために、プレイ情報（個人を特定しない）を送りますか？」［送る］［送らない］
- 選ぶまでは送らない。データ管理画面でいつでも変えられる。
- 説明ページ `privacy.html` を作り、集める内容・目的・保存期間・消し方を書く。

**識別子**
- 端末ごとにランダムな匿名ID（`anonId`）を作る。クラウドセーブのIDとは別にする。
- 「送ったプレイ情報を消す」を押すと、サーバー側でその匿名IDの情報を消し、IDも作り直す。

**送る内容**（許可リストにある種類だけ）

| 種類 | 中身 |
|---|---|
| `session` | 版、画面の大きさの区分（スマホ/PC）、AUTO・速度の設定、累計プレイ時間 |
| `run_end` | 開始階、到達階、クリア数、終わり方（敗北/撤退/打つ手なし）、かかった秒数、AUTOで打った割合、レベル、苦難 |
| `milestone` | 10・20…100階、200・300…階に初めて届いた時の累計プレイ時間 |
| `first_clear` | 初撃破までの累計プレイ時間、ラン数 |
| `reincarnate` | レベル、得た転生ポイント、転生回数、累計プレイ時間 |
| `trial` | 開始/達成/放棄、苦難のID |
| `item` | 買った秘宝のID・階 |
| `auto` | AUTO・周回・速度の切り替え |

**集計画面**
- `admin.html`：合言葉（`ADMIN_TOKEN`）を入れると `/api/admin/stats` から集計を取って表示する。
  - 節目ごとの到達時間（中央値など）
  - 敗北が多い階
  - 1ランの長さ
  - AUTOの利用率
  - 版ごとの人数
  - 苦難の挑戦数・達成数
- 生のデータは `/api/admin/export` で JSON として取り出せる（合言葉が必要）。
- `docs/playtest.md`：テストプレイヤーへの依頼文と、観察する点のチェックリスト。

**洗い出した問題と対処**
- 送信を待つと画面が止まる。→ 端末内の送信待ちに貯めて裏で送る。送信待ちは最大500件で、失敗したものは次の機会に送る。
- 合言葉を推測されて見られる危険がある。→ 長い合言葉を推奨し、照合は時間差の出ない比較で行う。失敗した回数に制限をかける。

## 6. 終盤の中身（エンドレスの新要素）

**特性**（101階から。敵1体に1つ、500階からは2つまで）
- 特性の付く確率：101〜199階 25%、200〜299階 40%、300階以上 60%。500階以上は、1つ目が付いたとき30%で2つ目も付く。
- 特性のある敵を倒すと、その階のソウルが1.5倍（特性2つなら2倍）になる。
- 特性は8種：

| 特性 | 効果 | 対策の方向 |
|---|---|---|
| 鉄壁 | 会心でない一撃のダメージ ×0.25 | 会心 |
| 再生 | 手を打つたびに最大HPの8%回復 | 一気に倒す |
| 呪縛 | バフの上乗せが半分 | 素の攻撃 |
| 瘴気 | 手数 −1 | 手数・効率 |
| 鏡面 | 処刑の火・猛毒が効かない | 通常攻撃 |
| 狂化 | HP×2（そのかわり獲得金額×2） | 火力 |
| 幻影 | その階で最初の攻撃・特殊カードは外れる | 弱いカードを先に使う |
| 硬化 | 1回のダメージは最大HPの30%まで | 手数・残滓の連撃 |

**深層の守護者**（200・300・400…階）
- 中ボスの代わりに出る。特性2つ（深さで決まる組み合わせ）と、HP×3。
- 倒すと、ソウル×3と、次の商人で秘宝が必ず1つ並ぶ。

**見た目**
- 今の絵を色替え（CSSフィルター）し、特性ごとのオーラと名札を付ける。
- 守護者はラスボスの絵の色違いにし、名前を「第N層の守護者」にする。
- 絵の指定はデータで持つので、後から新しい絵に差し替えられる。

**AUTOの対応**
- ダメージの見積もりに特性を入れる（鉄壁・硬化・幻影）。
- 鏡面の階では、処刑の火と猛毒は他に打てるカードがないときだけ使う。
- 幻影の階では、最初にいちばん弱い攻撃カードを捨て札にする。
- 硬化の階では、上限に届くカードがあればバフを積まない。

**洗い出した問題と対処**
- 鏡面で処刑の火を「使えない」にすると、手札に打てるカードが無くなって固まる恐れがある。→ 使えるが効かない（手数は減る）にする。
- 既存の不具合：処刑の火ばかりのデッキで1枚使うと、残りが使えず手数が残ったまま固まる。→ 打てるカードが1枚も無くなったら「打つ手がない」として敗北扱いにする。
- 硬化と瘴気、硬化と幻影が同時に付くと、打てる手が足りずに倒せない階ができうる。→ この2組は同時に付けない（守護者の組み合わせも同じ）。
- 鉄壁が効くのは、カードと残滓の会心でない一撃だけ。処刑の火と猛毒は割合のダメージなので、鉄壁は効かない（これらを止めるのは鏡面）。
- 特性で深層が重くなる分は、平均でHP×2〜3相当（到達階で約10階分）。到達点は大きくは変わらない。
- 苦難は100階で終わるので、特性とは重ならない。

**実績**：守護者を初めて倒す／10体倒す、特性のある敵を100体倒す。

## 7. 長期的な目標（転生ポイントの使い道）

**超越の刻印**
- 「特殊強化」（会心の覚醒→会心の暴走→神威の書き換え）の先に置く1つのノードで、何度でも買える。
- 1段ごとに全ダメージ×1.5。価格は 1,000万pt × 2.5^段。
- 魔法陣の完成度には数えない（それ以外を全部買えば完成として光る）。一括購入でも買わない（使い切ってしまわないように、手動で買う）。
- 苦難中は封印される。

**洗い出した問題**
- 際限なく伸ばして大丈夫か。→ 1段で価格は2.5倍、効果は1.5倍なので、ダメージは使ったポイントの約0.44乗でしか伸びない。
  掛け算なので伸びの傾きは変わらず、累乗のようにダメージの伸びが敵HPの伸びを超えて止まらなくなることはない。

## 8. セーブ（端末内の書き出し＋クラウドの引き継ぎ）

**データ管理画面**
- タイトルの「進行状況をリセット」を「データ管理」に置き換え、次をまとめる。
  1. **クラウドセーブ（引き継ぎ）**
     - 「引き継ぎを設定する」を押すと、サーバーが**引き継ぎコード**（例 `MT-7KQ2-9XWD`）と**パスワード**（10文字）を発行する。画面に大きく表示し、控えるよう案内する。
     - 設定した後は、自動でクラウドに保存する（10分ごと、転生したとき、画面を閉じるとき）。最後に保存した時刻を表示する。
     - 別の端末や、データが消えた端末で、コードとパスワードを入れると復元できる。
       復元すると世代番号が上がり、元の端末からの保存は「別の端末に引き継がれた」として止まる（2台から上書きし合うのを防ぐ）。
     - サーバーには最新と1つ前の2つを残す。どちらから復元するか選べる。
     - 「クラウドのデータを削除する」で、サーバー上のセーブを消せる。
  2. **端末内の書き出し・読み込み**（通信なしで使える控え）
     - 形式は `MT2:` の後に base64 化した JSON。ファイルで保存するか、文字列をコピーする。
  3. **プレイ情報の送信**のON/OFFと、送った情報の削除
  4. **進行状況のリセット**
- 読み込み・復元は、形式を確認してから上書きの確認を出し、書き込んで再読み込みする。
  リセットと同じ手順を使い、ゲームが古いセーブを書き戻さないようにする。

**サーバー側**
- パスワードは scrypt で塩付きハッシュにして保存する。
- 復元の失敗が10回続いたら、そのコードを1時間止める。IPごとにも上限を設ける。

**洗い出した問題と対処**
- 他人が作ったセーブを読み込むと、カード名に仕込んだHTMLが画面で実行されうる（カード名を innerHTML で表示しているため）。
  さらに、ランクを文字列にしても同じことが起きる（`Lv.${rank}` も innerHTML に入るため）。
  - カード名は、表示するときに必ずエスケープする。
  - セーブを読み込むたびに（通常の起動も含めて）、カードの数値（ランク・枚数・威力など）を数値に直す。パネルの段数などは上限の範囲に収める。
  - 知らないカードは消さない。古いセーブにある正規のカードを消してしまう危険があるため。
- 段数に1億などの値が入っていると、ループで固まる。→ 上の範囲の制限で防ぐ。
- 別の端末で読み込むと、時計のずれで「時を遡る者」が誤って解除されたり、放置収入が二重に入ったりしうる。→ 読み込んだときに最終確認時刻を現在に置き直す。
- コードとパスワードを控え忘れると、端末のデータが消えたときに戻せない。→ 設定した直後に「控えました」を押すまで画面を閉じない。データ管理画面でいつでも再表示できる（端末内に保存しておく）。
- 書き出したセーブやクラウドの中身を書き換えれば、数値の改造はできる。→ 対人の要素やランキングが無いので防がない（README に明記する）。

## 9. game.js の分割

- `src/` に機能ごとのファイル（12個前後）に分ける。公開用の `game.js` は、それを順に結合して作る（`node tools/build.js`）。
  - 中身は今の1つの関数のまま。動作は変わらず、外から中身に触れない状態も保てる。
  - 分割した直後は、結合したものが今の game.js と1文字も違わないことを確かめる。
- CIとプッシュ前のフックで、`game.js` が `src/` から作り直されているか確かめる。
- 文化祭版は別のコードなので、分けない。

**数値のキャッシュ**
- 先に、深い階・×4・残滓6体での1手あたりの処理時間を測る。
- 2ms未満なら入れない。キャッシュは、値が古いまま残る不具合を生みやすいため。

**洗い出した問題**
- ブラウザ標準のモジュール（import/export）にすると、共有している状態（save・game など）の参照を数百か所書き換えることになり、不具合の危険が大きい。→ 採らない。
- `src/` を直したのに結合し忘れると、公開物が古いままになる。→ プッシュ前のフックとCIで、ずれを検出する。

## 10. 秘宝の終盤での価値

**秘宝の覚醒**
- 上限まで持っている秘宝が、商人に「〇〇の覚醒」として並ぶ。
  - 1段ごとに、その秘宝の効果が +50%（秘宝の契約の「効果+%」と同じ扱い）。
  - 価格はその秘宝の通常価格 × 3^段。転生でリセットされる。
  - 終盤で使い道のなかったゴールドの使い道になる。
- 覚醒できるのは掛け算の秘宝だけ。累乗・手数・会心率・バフの秘宝は覚醒しない。
  - 累乗は暴走の危険がある。手数は固定値。会心率は100%で上限に当たる。バフは足し算で、際限なく積み上がるため。
- 新しい秘宝「破魔の護符」：特性のある敵へのダメージ×4。上限2。101階を越えてから並ぶ。覚醒できる。

**洗い出した問題**
- ゴールドが増える秘宝（黄金の天秤）を覚醒させると、ゴールドがさらに増えて覚醒が進む循環になる。
  → 効果は段数に比例してしか伸びず、価格は3倍ずつ上がるので収まる。テストで確認する。

## 実装の途中で見つかったこと・決めたこと

- **苦難のHP倍率が経験値も増やしていた**（経験値＝敵の最大HPのため）。堅牢★★★でラスボス時Lv131（苦難なしならLv77）と、制限が自分で打ち消されていた。
  → 苦難の倍率の分は経験値にしない（守護者・狂化のHP増は経験値にも乗せたまま）。
- **測ってみると、方向ごとの制限はほとんど効かない**（B＝苦難なしで約1,000枚に対して）：
  手数−2・会心なし・カード強化なし・バフ半減はどれも B×0.8〜1.3、攻撃力×0.001でも B×2.4、経験値×0.001でも B×2.2。
  効くのは敵HP（×1万で B×2.4、×100万で B×3.9、×10億で B×7.5）とソウルの倍率（×0.25で B×5.1）だけだった。
  → 各苦難は方向ごとの制限に加えて、目標に届くよう測った敵HPの倍率を持つ（数値と測定値は README の苦難の表、`src/05-trials.js`）。
- **飢餓★★★の「商人が何も売らない」は越えられない壁だった**（秘薬が無いと91〜99階を越えられず、3万枚使っても未達）。→ 外して、ソウル×0.2だけにした。
- **測定用ボットが秘薬を買っていなかった**（自動購入がオフ）。→ 自動購入をオンにして測り直した。
- **数値のキャッシュは入れない**：jsdom（実際のブラウザより遅い）でも、ダメージ計算の関数一式は1回0.15ms。
  時間がかかっているのは画面の組み立てで、キャッシュしても1手あたり2ms以上は縮まない。
- **分割**：`src/` の20ファイルに分けた。結合すると分割前の `game.js` と1文字も違わないことを確かめた。
- **全部入りの再測定**（`tools/sim/bot.js`、人の手のペースで数えた時間、3シード）：
  - ラスボス初撃破：0.46〜0.82時間（前回の測り方では1.4〜1.6時間。今回のボットはゲーム自身のAUTOでカードを選ぶので上手い）
  - 約10時間：912〜1,341階、最大の一撃 1E54〜1E77、転生1〜2回。止まらなくなる兆しはない（ループの中では伸びが鈍り、転生で跳ねる）
  - 最大ダメージの理論値（`tools/sim/maxcalc.js`）：拡張強化Lv25・刻印Lv10・覚醒5で約6,200階・1E324
