# マギア・タワー（アルファ版）

100階建ての塔をカードで登っていく、ブラウザ完結型のローグライト系デッキビルダー。
ランに失敗しても倒した敵の強さに応じた「ソウル」を持ち帰り、恒久強化を積み上げて再挑戦する。

ビルドツール・依存パッケージ・サーバーは一切不要。`index.html` を開けば動く静的サイト。

---

## 動かし方

```
git clone git@github-personal:aiking-01/magia-tower.git
cd magia-tower
```

そのまま `index.html` をブラウザで開くだけで動く（`file://` でも可）。
ただし `file://` ではダメージ数字の専用フォント画像が読み込めない（mask-image はCORS扱いのため）ので、通常のフォントで表示される。

ローカルサーバーで動かす場合:

```
python3 -m http.server 8000
# http://localhost:8000 を開く
```

デバッグコンソール（後述）はローカルでは常時有効なので、開発時はどちらでも構わない。

## ファイル構成

```
index.html        マークアップのみ。全画面が .screen として並んでいる
style.css         全スタイル。末尾にレスポンシブ用のブレークポイント

assets/
  title-banner.webp    タイトル画面のキーアート
enemies/
  01-goblin.png 〜 09-mushroom-skeleton.png   通常敵9体
  10-midboss.png       中ボス
  11-finalboss.png     ラスボス
  bg-dungeon.webp      通常敵の背後に敷くダンジョン背景
```

`game.js` の中は、上から順に「定数・敵/カード/スキルツリー定義 → セーブ処理 → 戦闘ロジック →
DOM 参照テーブル（`el`）→ 各画面の render 関数 → イベント登録 → デバッグコンソール → 初期化」。

## ゲームの流れ

```
タイトル ──「塔に挑む」──> 階層選択 ──> 戦闘 ──勝利──> フロアクリア（商人）──> 次の階層
   ^                                       │                    │
   │                                     敗北                 撤退
   └───────── ソウルを獲得して戻る ───────────────────────────┘
```

### 戦闘

- 1フロアにつき敵が1体。敵のHPを0にすれば勝ち。
- 手札からカードを選んで使う。使うたびに**残り手数 `n`** が1減り、0になった時点で敵が残っていれば敗北。
- 使ったカードは山札の一番下に戻る（デッキは尽きない）。デッキは最低9枚（`MIN_DECK_SIZE`）。
  手札より山札が少ないと使ったカードがすぐ戻ってきて同じカードを連打できてしまうため。
- カード種別は 攻撃 / 割合 / 特殊 / 連鎖 / バフ / 毒 の6種。
- ダメージ式（攻撃・特殊カード）:
  ```
  ダメージ = 威力 × (基礎倍率 + Σ(各バフ倍率−1)) ^ 累乗 × 最終倍率 × クリティカル倍率
  威力 = カードの基礎威力 + 基礎攻撃力（特殊カードは各カード固有の計算）
  ```
  - バフは次の攻撃・特殊カードに乗り、重ねると上乗せ分が**足し算**になる（×2と×3で+3）。
  - 指数的な伸びは**累乗**が担う。累乗は育成（基本強化の終末の力・神域への到達、転生パネルの継承の累乗・神威の書き換え、拡張強化の魂の極致）でのみ上がる。
  - 最終倍率は累乗の外側に掛かる掛け算。基本強化の「闘気」の枝（×1.1/×1.2/×1.3/×1.75、合計約×3）と拡張強化の「魂の昇華」で上がる。
  - 割合カードはこの倍率も会心も受けず、貯めたバフも消費しない（敵HPの成長を無視して確殺できてしまうため）。
  - 割合カード（処刑の火）は**1階につき1回まで**。使った後は、手札に残っている割合カードもその階では使えない（何枚も持って毎階確殺するのを防ぐため）。
  ドロー系は現在無効（`BASE_DECK_DEFS` にコメントアウトで残している）。

### 難易度カーブ

敵HPは1階の100を起点に、**1階進むごとに ×1.1**、**10の倍数階だけ ×1.4**。

```js
// game.js : computeFloorHp()
```

敵の見た目は通常敵9体を循環し（`ENEMY_ROSTER[(floor - 1) % 10]`）、10の倍数階は中ボス「死の賭博師」、
ちょうど100階がラスボス「塔の支配者」。中ボスとラスボスは背景が黒一色になる。

### 階層選択

10階刻みのチェックポイント（`1, 11, 21, ..., 91, 100`）から開始階を選べる。
到達済みかどうかに関わらず全て選択可能で、各カードに開始階のHPが表示される。
エンドレスも同じ10階刻み（`101, 111, 121, ...`）で、直前の階（100階・110階…）を**クリアすると**そこから始められる（転生でリセット）。
チェックポイントの一覧には101階と、到達済みの深い方から29か所を表示する。

## 3つの通貨

| 通貨 | 永続 | 入手 | 使い道 |
|---|---|---|---|
| **ソウル** | ✅ セーブされる | ランで**クリアした階の階数の合計**（例: 91階から3階クリア = 91+92+93 = 276pt） | 基本強化ツリー / デッキ強化 / カードショップ |
| **ゴールド** | ❌ ラン中のみ | フロアクリア時に `10 + 階数 × 3`（強化で倍率up） | フロアクリア画面の商人（そのラン限定の強化・リロール） |
| **転生ポイント** | ✅ セーブされる | **転生した瞬間**に、その時点のレベルから `10 × レベル²`（継承の記憶で増加） | 転生パネル・残滓の強化・残滓スキルツリー |

ソウルが「クリア階数の合計」なのは、高いチェックポイントへの挑戦が正当に報われるようにするため。

### 商人（フロアクリア画面）

- 秘薬の価格は `基本価格 + 階数×2`。強欲の秘薬（獲得金額+10%）は同じランで買うたびに×1.2、会心撃の秘薬は×1.1。
- 会心の秘薬は+1%で、1ランに30回まで。集中の秘薬は11階、強欲の秘薬は21階を**クリア**すると並ぶ。
- 集中の秘薬は出現率が他の約0.15倍（`weight`）で1ラン3個まで。手札+2がデッキ枚数以上になると並ばない（手札がデッキに追いつくと使ったカードがすぐ戻り、同じカードを連打できてしまうため）。
- 有料リロールは `(10 + 階数×2) × 1.5^(この訪問での有料リロール回数)`。無料リロール（基本強化）は別枠。
- **自動購入**（基本強化「自動購入開放」で解放）：「全部買う（安い順）→リロール」を所持金が尽きるまで素早く繰り返す。
  リロールは、払った後に一番安い秘薬をまだ買える場合だけ行う。「毎回自動で実行」をONにすると商人画面に入るたびに実行（設定は保存）。次の階への移動は手動。

### 恒久強化の3画面

- **基本強化** — ドラッグでパン / ホイール（スマホはピンチ）でズームするスキルツリー。攻撃力・手数・獲得金額などの枝に分かれる。
- **デッキ強化** — 所持カードの強化（ランク上げ / 基本15pt）・削除（基本20pt）・**編成枚数の増減**。
  強化も削除もカードごとに使うたび費用が2倍になる（基本強化の「経済の秘伝」を取っていれば1.5倍）。
  デッキは合計9枚未満にはできず、ダメージ源（攻撃/割合/特殊）も最後の1枚は削除できない（9枚未満の古いセーブは、控えのカードを編成に戻し、足りなければ斬撃を補充）。
- **拡張強化** — 転生パネルの「魂の拡張」1段ごとに1種類追加される、ソウルで何度でも強化できる項目（基本強化のタブ）。
  魂の鍛錬（攻撃力+10%）/ 魂の研磨（会心倍率×1.05）/ 魂の吸収（ソウル獲得+10%）/ 魂の昇華（ダメージ×1.1）/ 魂の極致（累乗+0.02）。
  1段ごとに価格が上がり（×1.35〜×2）、転生でレベルはリセットされる（`TREE_EXT_DEFS`）。
- **カードショップ** — 転生パネルの「商人との契約」を1段でも取ると解放される。強力なカードを購入できる。
  同じカードは買うたびに価格が1.5倍になる（`CARD_SHOP_PRICE_GROWTH`、購入回数は`cardShopPurchases`に保存し転生でリセット）。
  この契約はレベルを上げるほど品揃えが増える（`PANEL_SHOP_CHAIN` / 最大レベル = `CARD_SHOP_POOL` の件数）。

### エンドレスと転生

100階のラスボスを倒すと、**エンドレスモード（101階〜）へ進むか、タイトルへ戻るか**を選べる。
ラスボス到達時点で転生パネルが恒久解放される。

転生すると、レベル・ソウル・基本強化（拡張強化を含む）・デッキが初期化され、その時点のレベルに応じた転生ポイントを得る。
**転生パネル・転生ポイント・実績・残滓（デッキとスキルツリー）は残る。**
タイトルの「転生パネルを見る」で、転生前にパネルを閲覧できる（購入は転生後）。

転生パネルの主な項目：継承の力（基礎攻撃力、1段ごとに効果2倍・価格×2.2）、神威の書き換え（累乗+0.2、100万pt）、魂の拡張（拡張強化の追加）など。

### レベル

- 敵を倒すと、その敵の最大HPと同じだけ経験値を得る。レベルごとの必要経験値は `50 × 1.2^(レベル−1)`。
- レベル1ごとに攻撃力+3%（基礎攻撃力の合計に掛かる割合）と会心ダメージ+1%（基本強化ツリーの上限の外）。
- レベルは転生まで持ち越す。上限はない。数値は `LEVEL_*` / `TRANSCEND_*` 定数で調整する。

### 実績

- タイトルの「実績」から一覧を見られる。効果は全て足し算で、転生しても失われない。
- 10〜90階の中ボス（死の賭博師）それぞれに撃破実績がある（賭博師討伐・其の一〜其の九、攻撃力+5〜25%）。
- 会心の連続は1回の挑戦（ラン）の中で数え、階をまたいでも途切れない（割合カードは会心しないので連続にも影響しない）。
- 隠し実績「時を遡る者」は、端末の時計が前回起動時より過去に戻っていると達成（放置収入はその回は得られない）。
- 内容は `ACHIEVEMENTS` 配列で定義（仮の内容）。

### 残滓

- 転生パネルの「残滓の召喚」で1段ごとに1体召喚（最大6体、価格は1段ごとに×5）。
- プレイヤーが攻撃・割合・特殊カードを使うたびに、全ての残滓が自分のデッキから1枚引いて順に追撃する（水色のダメージ）。
  追撃のダメージは `直前のプレイヤーの一撃 × (カードの比率 × (1 + 0.5×ランク) + 残滓の力) % × (1 + 残滓の猛威%)`。
  カードの比率は残滓の爪5%・残滓の牙12%（`REMNANT_CARD_PCT`）。基準がプレイヤーの一撃なので、バフ・累乗・会心も実質的に乗る。
  追撃するのは攻撃・特殊カードの後だけ。処刑の火（割合）の後には追撃しない（最大HPの割合に追撃が乗ると、どの階も1手で倒せてしまうため）。
- 1体目を召喚すると、タイトルの「基本強化」が「プレイヤー強化」（基本強化／デッキ強化のタブ）に、「デッキ強化」が「残滓強化」（残滓／残滓スキルツリーのタブ）に変わる。
- 残滓のカード強化・残滓スキルツリーは転生ポイントで購入し、転生してもリセットされない。
- 残滓スキルツリーは4つの枝がそれぞれ30段（`REMNANT_TREE_STEPS`）。1段ごとに価格は×1.5、効果も少しずつ大きくなる（残滓の力・猛威は×1.15ずつ）。
  全段の合計は 追撃の比率+436pt・残滓のダメージ+4,349%・放置の上限+30時間・放置収入+600%、費用は合計約2億pt。
- **放置収入**：残滓がいると、ゲームを閉じている間も1分あたり「クリアした最高階のHP×0.02」の経験値と「その階数×0.25」のソウルを残滓の数だけ稼ぐ。
  上限は2時間分（残滓の刻で延長）。タブを表示している間は加算せず、非表示にしていた時間は戻ったときに同じ計算で加算する。

## 巨大数（break_infinity.js）

敵HP・ダメージ・倍率・経験値・最大ダメージ記録は、JavaScriptの数値の上限（約1.8E+308）を超えられるよう
[break_infinity.js](https://github.com/Patashu/break_infinity.js)（MIT、`vendor/` に同梱）の `Decimal` で扱う。
上限は約 1E+9,000,000,000,000,000 で、敵HPがそこに届くのは約10京階。
ゴールド・ソウル・転生ポイント・攻撃力・レベルは通常の数値のまま。
10億以上は `1.23E+45` 形式で表示し、指数が1万以上なら `1.23E+12,345` のように桁区切りを入れる。

## セーブデータ

`localStorage` のキー `magiaTower.save.v2` に JSON で保存。サーバー通信は一切ない。

```
points  unlockedNodes  bestFloor  deckDefs  startCardsBackfilled
transcendPoints  panelLevels  panelSpecials  transcendUnlocked  cardShopPurchases  bestClearedFloor  autoBuyEnabled
level  exp  achievements  stats  remnantDecks  remnantTree  lastSeen  treeExt
```

- ロード時は `defaultSave()` にマージするので、**フィールドの追加は既存セーブを壊さない**。
  既存フィールドの意味を変える場合はマイグレーションが必要（`loadSave()` に前例あり）。
- ゴールドはラン中の状態でありセーブされない。
- `exp` と `stats.maxHit` は `Decimal` を文字列（例: `"1.23e+600"`）で保存する。古いセーブの数値や `null` も読み込める。
- 全消去はタイトル画面下部の「進行状況をリセット」から（確認ダイアログあり。`window.confirm` は一部のブラウザ埋め込み環境で表示されないため、自前の `showConfirm()` を使う）。

## 開発者向け

### デバッグコンソール

DevTools のコンソールで `mt` が使える。

```js
mt.points              // ソウルを表示
mt.points = 9999       // 設定（代入した時点で自動セーブ＋画面に即反映）
mt.addPoints(500)      // 加算（マイナスで減算）
mt.setPoints(0)

mt.gold                // ゴールドを表示（ラン外は null）
mt.gold = 9999         // 設定（ラン中のみ。セーブはされない）
mt.addGold(500)
mt.setGold(0)

mt.transcend           // 転生ポイントを表示
mt.transcend = 9999    // 設定（自動セーブ＋画面に即反映）
mt.addTranscend(500)
mt.setTranscend(0)
mt.unlockTranscend()   // 転生パネルを解放（通常はラスボス撃破で解放される）

mt.help()              // 使い方を表示
```

転生ポイントは、ラスボスを倒すまでタイトルに表示も「転生」ボタンも出ない。
未解放のまま `mt.transcend` に値を入れても使い道がないので、その場合は警告が出る。
`mt.unlockTranscend()` を実行すればタイトルに「転生」ボタンが現れ、パネルを開けるようになる。

> **注意**: タイトルの「転生」ボタンは、確認ダイアログでOKするとソウル・基本強化・
> デッキ編成・最高到達階をその場で消す。転生パネルを見るだけの導線は無いので、
> 消したくない進行状況があるならバックアップを取ってから押すこと（下記）。

セーブデータの退避・復元:

```js
copy(localStorage.getItem('magiaTower.save.v2'))        // クリップボードへ退避
localStorage.setItem('magiaTower.save.v2', '<貼り付け>')  // 復元（実行後リロード）
```

有効になる条件（`game.js` 冒頭の `DEV_CONSOLE`）:

| 環境 | `mt` |
|---|---|
| `localhost` / `127.0.0.1` / `file://` | **常に有効** |
| デプロイ先 | `?debug=1` を付けた時のみ |

> DevTools に「Don't paste code you don't understand」の警告が出たら、`allow pasting` と**手入力**して Enter。
> 手打ちなら警告は出ないので、短いコマンドは直接打つのが早い。

### デバッグカード

URL に `?debug=1` を付けると、戦闘開始時の手札に「【DEBUG】即死」「【DEBUG】確定会心」が追加される。
フロアクリア以降の画面を確認したい時に使う。

## 動作環境

デスクトップ / タブレット / スマートフォンに対応。

| ブレークポイント | 挙動 |
|---|---|
| `860px` 以下 | 戦闘画面を1カラムに |
| `640px` 以下 | スマホ向けレイアウト（手札3列、選択肢1列、デッキ行の折り返し） |
| `400px` 以下 | 小型端末向けにさらに圧縮 |
| 横向き（高さ520px以下） | 高さが足りないため戦闘画面を2カラムに戻す |

- hover 演出は `@media (hover: hover)` で囲ってあるので、タッチ端末でタップ後に選択状態が残らない。
- スキルツリー / 転生パネルはタッチでのドラッグパンとピンチズームに対応。
- 戦闘画面の敵画像の高さは JS（`syncEnemyVisualHeight()`）でログ欄の高さに合わせている。
  1カラムに切り替わる条件は CSS と `isStackedBattleLayout()` の**両方**にあるので、変更時は揃えること。

## デプロイ

GitHub Pages を想定。Settings → Pages で `main` ブランチのルートを指定すれば、ビルド不要でそのまま公開できる。

デプロイ前に把握しておきたい点:

1. **キャッシュ** — `style.css` / `game.js` は長めにキャッシュされる。更新時は `?v=2` のようなクエリを付けるなど、
   「新しいHTML × 古いJS」の組み合わせが起きないようにする。
2. **画像の重さ** — 敵PNGが合計約3.7MB（1体あたり190〜540KB）。戦闘開始時に都度読み込むため、
   モバイル回線では階層移動のたびにダウンロードが走る。WebP化と先読みが未対応。
3. **リポジトリの公開設定** — private リポジトリで Pages を使うには GitHub Pro 以上が必要。
   public にするとゲームバランスの数値がすべて読める（クライアント完結型なので、いずれにせよ改変は防げない）。
4. **`?debug=1`** — 公開環境でもデバッグカードとデバッグコンソールが有効になる。URLを知られれば誰でも使える。

## 文化祭体験版（`festival/`）

展示用に、ラスボス討伐までを15〜20分に縮めた別バージョン。本編のファイルには一切手を入れておらず、
`festival/` フォルダの中だけで完結している（敵画像・背景・ライブラリは `../enemies/` などを本編と共有）。

### 遊び方・開き方

- 公開先では `https://<公開URL>/festival/` を開く。
- 展示用PCなどでは `festival/index.html` をダブルクリックで開くだけでも動く（ダメージ数字の画像も出る）。
  インターネット接続は不要。全画面にするときは F11。
- 本編とはセーブが別（`magiaTower.festival.v1`）なので、同じブラウザで本編を遊んでいても干渉しない。

### 展示の運用

- 1人が遊び終わったら、タイトル画面下の **「次の人へ（プレイデータを消去）」** を押す。
- 画面右上（スマホは右下）にプレイ時間が出る。最初に「塔に挑む」を押した瞬間から、ラスボスを倒すまでがクリアタイム。
- クリアするとニックネームを入れてランキングに登録できる。ランキングは「次の人へ」では消えない。
  消したいときは DevTools のコンソールで `mt.clearRanking()`（ローカルか `?debug=1` のときだけ使える）。

### 本編との違い

| | 本編 | 文化祭体験版 |
|---|---|---|
| 塔 | 100階＋エンドレス | 30階（10・20階が中ボス、30階がラスボス） |
| 敵HP | 1階ごとに×1.1 | log10(HP) が1階ごとに `0.1×1.2^(階−1)` 増える＝加速度的に増える。ラスボスはちょうど 1E+100（1グーゴル） |
| ダメージ | 威力 × (1+Σバフ)^累乗 × 最終倍率 × 会心 | (威力 × バフ倍率 × 闘気 × 会心)^累乗。累乗が全部に掛かる |
| レベル | 攻撃力+3%/Lv | 攻撃力 ×1.5/Lv（必要経験値は ×3/Lv）。終盤は1階で数十レベル上がる |
| ソウル | クリアした階数の合計 | その1.3倍 |
| テンポ | — | カードのアニメーション短縮、数字キー1〜9で手札を使う、Enterで次の階、自動購入が最初からON、敗北画面から直接「基本強化へ」 |
| 演出 | — | 一撃が万・億・兆…無量大数・グーゴルの位に届くたびに大きな漢字の演出、敵HPに「2.4万」「34垓」のような表記 |

**封印**（ボタンやノードは見えるが、押すと「完全版で解放」の予告が出るだけ）：
デッキ強化・カードショップ・実績・転生・残滓・エンドレス・31〜100階・基本強化ツリーの先（「？？？」ノード）。
予告文は `festival/game.js` の `SEALED_FEATURES` にまとまっている。
本編にある処刑の火（割合）・猛毒・放置収入は、体験版では存在ごと外している。

### バランス調整

```
node festival/tools/balance-sim.js
```

ボットが「挑戦→敗北→安い順に強化→再挑戦」をクリアまで繰り返し、人間のペースを仮定したクリア時間を出す。
現在の数値で中央値およそ17〜18分（5回目の挑戦でクリア）。`festival/game.js` の数値を変えたら、
シミュレーター冒頭の `P`・`TREE` も合わせて直してから実行すること。

`festival/dmg-glyphs.js` は `assets/dmg-font/*.png` を data URI にした自動生成ファイル
（`file://` で開いてもダメージ数字の画像を出すため）。グリフ画像を差し替えたら、リポジトリ直下で次を実行して作り直す:

```
python -c "import base64,glob,os;print('window.MT_DMG_GLYPHS = {'+','.join('\"%s\": \"data:image/png;base64,%s\"'%(os.path.splitext(os.path.basename(p))[0],base64.b64encode(open(p,'rb').read()).decode()) for p in sorted(glob.glob('assets/dmg-font/*.png')))+'};')" > festival/dmg-glyphs.js
```
